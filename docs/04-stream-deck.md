# 04. Stream Deck から送る

bridge は「URL を GET で叩かれたら送る」だけなので、Stream Deck 側は URL を叩ければ何でも構いません。

## 方法 A: 標準の「Web サイト」アクション

1. Stream Deck アプリで「システム」→「Web サイト（Website）」をボタンに配置
2. URL に次を入力

   ```
   http://127.0.0.1:50002/send?text=hello
   ```

3. **「バックグラウンドで GET リクエスト」（GET request in background）** を選ぶ
   - これを選ばないとブラウザで URL が開いてしまいます
   - 表記は Stream Deck アプリのバージョンによって異なります

日本語などを送るときは URL エンコードしておくと確実です（例: `テスト` → `%E3%83%86%E3%82%B9%E3%83%88`）。
ブラウザのアドレスバーではなく、次で変換できます。

```bash
node -e "console.log(encodeURIComponent(process.argv[1]))" "ロキソニン錠60mg"
```

## 方法 B: 「開く（Open）」アクションで curl を実行

「Web サイト」アクションにバックグラウンド実行がない場合は、「システム」→「開く」で次のようなコマンドを実行させます（Windows 10 以降には curl が標準で入っています）。

```
curl -s "http://127.0.0.1:50002/send?text=hello"
```

## 方法 C: HTTP リクエスト系のプラグイン

Stream Deck ストアには、HTTP リクエストを送り応答を表示できるプラグインがあります。結果（`done` / `failed`）をボタンに表示したい場合はこちらが便利です。

## 動作確認のコツ

先に curl で `done` が返ることを確認してから Stream Deck に設定すると、問題の切り分けが楽です。

| curl の結果             | 意味                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| 接続できない            | bridge が起動していない                                                                     |
| `no-client`             | 拡張がつながっていない（対象ページを開いているか、丸が緑か）                                |
| `skipped: 対象外の URL` | 開いている画面が `sites.js` の `urlPattern` に合っていない                                  |
| `skipped: タブが非表示` | 対象ページのタブが前面にない（Chrome が最小化・他のウィンドウに完全に隠れている場合も含む） |
| `failed: ...`           | `run()` の中で失敗。メッセージと DevTools の Console を確認                                 |
| `done`                  | 成功                                                                                        |

## bridge を毎回起動しないといけないのか

この構成では、Stream Deck から送るために bridge（`npm start`）が起動している必要があります。専用のアプリを作る必要はなく、用途に応じて次のどれかにします。

| 段階             | 方法                                                                                                         | 向いている場面                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| 学習・検証       | 今のまま `npm start` を手で起動                                                                              | curl で 1 段ずつ確かめたいとき                                      |
| 毎日使う（簡易） | Windows のスタートアップに登録（`shell:startup` にショートカット、またはタスクスケジューラで「ログオン時」） | PoC をそのまま使い続けるとき                                        |
| 本番に近い形     | **bridge を Stream Deck プラグインの中に入れる** → [05-streamdeck-plugin.md](05-streamdeck-plugin.md)        | 別プロセスをなくし、設定・結果表示も Stream Deck で完結させたいとき |

### そもそも拡張がいらない場合

「今カーソルがある欄に、決まった文字列を打ち込む」だけなら、Stream Deck 標準の **「テキスト（Text）」アクション** で足ります（キーボード入力として打ち込む機能）。拡張も bridge も不要です。

拡張が必要になるのは次のような場合です。

- カーソル位置に関係なく、**特定の欄を狙って** 入れたい
- 1 回の押下で **複数の欄に振り分け** たい、ボタンまで押したい
- **特定の URL（画面）でだけ** 動かしたい、結果（成功・失敗）を知りたい
