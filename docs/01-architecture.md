# 01. 仕組み

## 登場人物

| 部品                 | どこで動くか          | 役割                                                             |
| -------------------- | --------------------- | ---------------------------------------------------------------- |
| Stream Deck          | PC 上のアプリ         | ボタンが押されたら URL を叩く（HTTP GET）                        |
| bridge               | PC 上の Node プロセス | HTTP を受けて、つながっている拡張に WebSocket で転送             |
| コンテンツスクリプト | Chrome の対象ページ内 | bridge につないで待ち受け、指示が来たら DOM を操作して結果を返す |

## 1 回のボタン押下で起きること

1. Stream Deck が `GET http://127.0.0.1:50002/send?text=hello` を送る
2. bridge がクエリを `payload = { text: "hello" }` にして、接続中の全タブへ `{"type":"fill","id":"...","payload":{...}}` を送る
3. 各タブのコンテンツスクリプト（`content.js`）が判断する
   - タブが見えていない → `skipped`
   - URL が `sites.js` のどの `urlPattern` にも合わない → `skipped`
   - 合う → その `run(payload, dom)` を実行し、成功なら `done`、例外なら `failed`
4. 各タブが `{"type":"ack","id":"...","status":"done",...}` を返す
5. bridge は全タブの返事（最大 3 秒）を集めて HTTP の応答として返す。`done` が 1 つでもあれば 200、なければ 409

## 「特定の URL でだけ動く」の二段構え

1. **`manifest.json` の `content_scripts.matches`** — Chrome がコンテンツスクリプトを読み込むページ。ここにないサイトでは拡張のコードは一切動かない。ワイルドカードの書式は [Chrome のドキュメント](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns) を参照
2. **`sites.js` の `urlPattern`（正規表現）** — 読み込まれたページのうち、実際に操作してよい画面をさらに絞る。例: 同じドメインでも「処方画面だけ」

さらに bridge 側の `ALLOWED_ORIGINS` は、WebSocket 接続を受け付けるサイトのオリジン一覧です。**サイトを追加したらこれらをそろえて変更** します（プラグイン版を使う場合は `streamdeck-plugin/src/hub.ts` の `ALLOWED_ORIGINS` も）。

## なぜコンテンツスクリプトから直接 WebSocket でつなぐのか

Manifest V3 の拡張には「バックグラウンド（Service Worker）」もありますが、アイドル状態で 30 秒ほどで止められるため、常時接続を持たせるには工夫が要ります。
コンテンツスクリプトはページを開いている間ずっと生きているので、そこから直接つなぐのが最も簡単です。ページごとに 1 本の接続になり、「どのタブが実行するか」はタブ側で判断できます。

## 値の入れ方の勘所

`dom-helpers.js` の `setValue` を参照。`input.value = "..."` と代入するだけだと、React / Vue などで作られた画面は **入力されたことに気づかない** ことがあります（見た目は入っているのに送信すると空、など）。ブラウザ本来の value セッターで値を入れ、`input` / `change` イベントを発火させるのが定石です。

それでも反応しない画面（独自のエディタ、`contenteditable`、iframe 内のフォームなど）は [03-adapt-to-your-site.md](03-adapt-to-your-site.md) を参照。

## セキュリティ

ローカルに「叩けば入力されるサーバ」を置くことになるので、最低限次を入れています。

| 対策                                          | 防いでいること                                                                                                  |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `127.0.0.1` でのみ待ち受け                    | LAN 内の他の PC から叩かれる                                                                                    |
| WebSocket の Origin 制限（`ALLOWED_ORIGINS`） | 関係ない Web サイトが bridge につないで、流れるデータ（患者情報など）を受け取る                                 |
| `Sec-Fetch-Site` 付きリクエストの拒否         | ブラウザで開いた悪意あるページが `/send` を叩いて勝手に入力させる                                               |
| `BRIDGE_TOKEN`（任意）                        | 同じ PC 上の他のプログラムから叩かれる。`BRIDGE_TOKEN=xxxx npm start` で有効化し、URL に `&token=xxxx` を付ける |

本番で使うなら、さらに「入力だけして送信は人が押す」「操作ログを残す」などを検討してください。
